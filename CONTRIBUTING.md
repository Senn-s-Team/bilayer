# Contributing to Bilayer

Thanks for taking a look. This is a small, dependency-free Safari web extension; the
whole point of the layout is that a change stays local and reviewable.

## Requirements

- macOS with full Xcode (only for building the Safari app wrapper; `npm run check`
  and `npm test` run anywhere Node runs)
- Node.js >= 22

## Setup

```bash
git clone https://github.com/Senn-s-Team/bilayer.git
cd bilayer
npm run check   # manifest, version sync, and syntax
npm test        # behavior regressions
```

There is nothing to install — the project has no runtime or dev dependencies.

## Layout

- `extension/` — the WebExtension source. This is the only place extension behavior lives.
- `extension/icons/` — `icon-source.png` is the single hand-maintained icon source. Never edit
  the PNGs directly; run `npm run icons` instead.
- `scripts/` — local checks, icon derivation, and Safari project generation. Nothing here
  ships inside the extension.
- `SafariApp/` — generated by `npm run safari:project`. Never edit it by hand, and it is
  not committed.

## Rules that matter

1. **Bump the version in two places.** `extension/manifest.json` and `package.json` must
   always agree; `npm run check` fails the build if they drift. `npm run safari:project`
   syncs `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` from the manifest.
2. **Never change the bundle identifier casually.** The host app id must stay a prefix of
   the extension id. Changing it makes Safari treat the extension as new, which drops every
   existing install's settings, provider credentials, and site grants.
3. **Never put a third-party trademark in the name, icon, or metadata.** Apple rejects
   extensions that use another company's marks in their branding.
4. **Keep internal docs out of user-facing strings.** `CLAUDE.md` files are agent context,
   not product copy.
5. **No new dependencies without a good reason.** The zero-dependency check path is a feature.

## Adding a display language or subtitles feature

Subtitle parsing, timing, and rendering are platform-independent: Netflix-specific private
behavior belongs in `extension/src/content/netflixAdapter.js`, and subtitle format handling
belongs in `extension/src/content/subtitleParser.js`. Do not leak provider credentials out of
the background context.

## Tests

`npm test` runs Node's built-in test runner over `scripts/*.test.mjs`. These tests drive the
real source files, so they catch real regressions. If your change alters observable behavior,
add or update a test that fails before and passes after your change.

`cases/` holds captured real-world provider responses used as parsing fixtures. If you add
one, redact any subtitle text that is not yours to redistribute.

## Submitting

- Keep a change focused; do not mix a refactor with a feature.
- Run `npm run check && npm test` before opening a pull request. CI runs both.
- Describe the observable behavior change, not just the files touched.
